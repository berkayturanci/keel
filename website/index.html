keel ⚓

A project-neutral, multi-agent workflow core. One fixed backbone drives a GitHub issue from backlog to merged — every project just sets values and snaps in its own Lego.

100% line + branch coverage stdlib-first · 1 runtime dep Python ≥ 3.11 📊 coverage report → GitHub →

What it is

keel is a ship's backbone — the fixed spine every project builds on. The same flow runs whether the coding agent is Claude Code, Codex, Gemini or Antigravity; projects never fork the backbone, they only:

① set values

A small .keel/project.yaml: base branch, build/lint commands, timezone & merge window, file globs.

② snap in Lego

Add-only extensions into named slots (reviewers, tester, pre-merge…). The backbone stays fixed.

The backbone

stepdoesslot
branch → implementcut a branch, agent writes the codeafter-implement
classify → cirisk tier (→ reviewer count), wait on CI

merge → closemerge-window + lock, then close the issuepre-merge

Install

pip install "git+https://github.com/berkayturanci/keel@v0.3.0"

Quickstart

Scaffold a config (with the wizard)

keel init --wizard
# Base branch [main]: main
# Merge window HH:MM-HH:MM [07:00-01:30]: 07:00-01:30
# Build/test command [flutter test]: flutter test
# → wrote .keel/project.yaml  (detected stack: flutter)

See what ship would do, right now

keel ship .keel/project.yaml --root .
# keel ship — myapp  (base main)
#   risk tier     : TIER-3  → 3 reviewer(s)
#   merge window  : OPEN
#   gate build          ok
#   gate lint           ok
#   decision      : MERGE — clear to merge

Commands

commandwhat
keel init [--wizard]scaffold .keel/project.yaml (detects the stack)
keel validate <cfg>validate a config against the schema
keel plan <cfg>render the backbone with this project's gates
keel run-gates <cfg>run the project's build/lint/command gates
keel window <cfg>is the merge window open now?
keel ship <cfg>full dry assessment: tier, window, gates, decision

Runs on the free runner

The keel-ship GitHub Action runs keel against every PR on GitHub's free hosted runner — using the runner's own git + gh — and posts the assessment as a comment. This very site & its coverage report are built and deployed the same way.
