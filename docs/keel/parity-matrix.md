# Legacy-to-keel command parity matrix

This matrix tracks whether a project can replace a legacy workflow command with the
corresponding `/keel:<command>` adapter without losing behavior.

The migration target is:

- legacy command wrappers become thin calls into keel after their row is marked
  `parity-proven`.
- keel-owned behavior lives in core runtime, transport, planning, adapter, or backbone
  contracts.
- project-owned behavior lives in `.keel/project.yaml`, project policy packs,
  `.keel/extensions/`, or project-provided commands.
- no consumer project policy is copied into packaged keel command bodies.

## Status vocabulary

| status | meaning |
|---|---|
| `not-started` | The row is documented, but parity work has not started. |
| `in-progress` | The owning issue is actively reducing known gaps. |
| `blocked` | The row cannot progress until a listed dependency ships. |
| `parity-proven` | The legacy behavior is represented by keel core, runtime, policy, extensions, adapters, or wrappers, and the row has evidence. |
| `deferred` | The gap is intentionally not being migrated yet, with a documented reason. |

## Update rules

- Keep the columns stable so each owning issue can update its row without changing the
  matrix structure.
- Every known gap must link to at least one GitHub issue.
- When a row reaches `parity-proven`, add evidence in the row rather than deleting its
  history.
- If a behavior is intentionally not migrated, mark the row or specific gap `deferred` and
  link the deferral rationale.
- Do not add consumer project names, private paths, product policy, path globs, or
  project-only commands to this document.

## Triage parity details

`/keel:triage` preserves the legacy backlog-hygiene surface with this exact mapping:

| Legacy behavior or flag | Keel mapping | Notes |
|---|---|---|
| default live run | `/keel:triage` | Reads open issues missing `status:*`, classifies, comments, and adds labels after consent. |
| dry run | `/keel:triage --dry-run` | Performs reads/classification, prints `DRY-RUN:` comment/label actions, and skips all writes. |
| label filter | `/keel:triage --label <name>` | Filters candidates to issues already carrying `<name>`. |
| role/routing assignment | `/keel:triage --assign` | Adds the configured routing role only when the issue has no role label. Without it, the role is suggested only. |
| classifier subagents | read-only classifier prompt | Subagents may read issue context but cannot comment, label, close, or edit. |
| closed label vocabulary | repo labels plus project `implementer_agents` role keys | Out-of-vocabulary classifier output is skipped, never guessed or created at runtime. |
| MCP label writes | explicit union of existing + added labels | MCP update calls overwrite labels, so the adapter must preserve existing labels and log added vs. preserved labels. |
| meta/tracking issues | empty status label allowed | The audit comment may be posted, but the status label can intentionally be omitted. |

Consumer projects migrating from legacy `platform:*` labels have two safe paths: keep
matching `implementer_agents` role keys during the transition, or translate legacy platform
values to configured routing roles in the wrapper before calling keel. Packaged keel command
bodies do not invent `platform:*` labels, and keel core does not broaden the project label
vocabulary at runtime.

## Stale PR parity details

`/keel:stale-prs` preserves the legacy stale-PR sweep with this exact mapping:

| Legacy behavior or flag | Keel mapping | Notes |
|---|---|---|
| default comment-only run | `/keel:stale-prs` | Reads stale PRs and posts at most one triage comment per PR. No branch refresh, close, merge, or CI rerun. |
| threshold | `/keel:stale-prs --days <N>` | Uses calendar days and rejects zero, negative, and non-integer values. |
| dry run | `/keel:stale-prs --dry-run` | Prints intended comments and refreshes, performs no API write and no git checkout/merge/push. |
| refresh drifted PRs | `/keel:stale-prs --rebase` | Cleanly merges configured `base_branch` into drift-bucket non-draft PR heads and pushes. |
| legacy refresh alias | `/keel:stale-prs --merge-develop` | Alias for `--rebase`; it still uses configured `base_branch`, never a hardcoded `develop`. |
| bucket priority | drift > review-stalled > likely-abandoned | A PR matching multiple buckets uses the highest-priority bucket. |
| author notification | mandatory `@author` mention in the comment | Every posted triage comment names the PR author. |
| same-day idempotency | first line starts `STALE-PRS-<DATE>-` | Existing comments with that prefix for the project-local date suppress duplicate posts. |
| conflict handling | abort and record `conflict-skipped` | The adapter runs `git merge --abort`, never auto-resolves arbitrary conflicts, and continues to the next PR. |
| local session report | summary table | The summary records PR, title, bucket, and action. Project report sinks remain project policy. |
