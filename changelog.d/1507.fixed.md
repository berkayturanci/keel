- **Merge retries accept PR checkpoints at s10 across runs on the same head, and refusals suggest resolving commands** (#1507). A failed merge retried on the same head no longer stalls on checkpoint run ID mismatches: `keel merge` accepts the PR's latest checkpoint at `s10` when its recorded head SHA matches the PR's current head, carries it forward upon landing, and records provenance in `carried_from_run_id`. When evaluating cross-run acceptance, checkpoints from earlier heads or those missing head provenance are refused with an explicit head-mismatch reason; same-run checkpoints continue to be evaluated without requiring cross-run head provenance. Refusals for missing gates-pass records, missing run IDs, missing checkpoints, and stale-step checkpoints print safely-quoted suggested resolving commands using verified CLI flag names (`--pull-request`, `--head-sha`, `--approve-scope`, `--operator`), with shell-safe placeholders (e.g. `'<new-run-id>'`, `'<operator>'`, `'<scope>'`) that the operator substitutes before execution.
