- **Merge retries accept PR checkpoints at s10 across runs on the same head, and refusals suggest resolving commands** (#1507). A failed merge retried on the same head no longer stalls on checkpoint run ID mismatches: `keel merge` accepts the PR's latest unmerged checkpoint at `s10` when its recorded head SHA matches the PR's current head (and matches `accepted_run_ids` when `--run-id` overrides the gates-pass run), carries it forward upon landing (with an explicit `adopt` gate flag, failing closed before any same-run shortcut if the reread checkpoint's source `run_id`, `pull_request`, or `head_sha` provenance is missing or changed, or if `state.merge` is already `merged` or `pending`), and records provenance in `carried_from_run_id`. Checkpoints already marked `merged` (`already-merged`) or `pending` (`in-flight`), or those from earlier heads or missing head provenance (`stale-head`), are refused; same-run unmerged checkpoints continue to be covered and updated without requiring cross-run head provenance. Refusals for missing gates-pass records, missing run IDs, missing checkpoint files, and stale-step checkpoints print safely-quoted suggested commands (`keel ship` omits `--run-id` and `--capture-status` so unedited execution fails fast rather than attesting `not-run` or recording placeholder literals, and foreign-run checkpoint refusals omit `--write` so another run's checkpoint is not overwritten).
