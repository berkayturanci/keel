- **Merge retries accept PR checkpoints at s10 across runs, and gates refusals name resolving commands** (#1507). A failed merge retried on the same head no longer stalls on checkpoint run ID mismatches: `keel merge` accepts the PR's latest checkpoint at `s10` and carries it forward to the new run upon landing. Refusals for duplicate capture markers, missing gates-pass records, missing run IDs, and missing or stale checkpoints now explicitly state the resolving command (`keel ship ... --run-id <new-id> --capture-status not-run` or `keel checkpoint ... --step <step>`).
