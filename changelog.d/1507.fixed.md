- **Merge retries accept PR checkpoints at s10 across runs on the same head, and refusals print runnable resolving commands** (#1507). A failed merge retried on the same head no longer stalls on checkpoint run ID mismatches: `keel merge` accepts the PR's latest checkpoint at `s10` when its recorded head SHA matches the PR's current head, carries it forward upon landing, and records provenance in `carried_from_run_id`. Checkpoints from earlier heads are refused with an explicit head-mismatch reason. Refusals for duplicate capture markers, missing gates-pass records, missing run IDs, and missing or stale checkpoints print runnable resolving commands using verified CLI flag names (`--pull-request`, `--head-sha`, `--approve-scope`, `--operator`).
