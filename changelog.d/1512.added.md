- **`keel stale-blockers` lists open PRs whose stated blocker has cleared** (#1512). A PR body that says `blocked by #N`, `depends on #N` or `do not merge before #N|<tag>` is checked against GitHub. `/keel:stale-prs` and `/keel:morning` run it and surface the result.
  - A blocker is `cleared` when its PR merged, its issue closed as completed, or its tag exists; a PR closed unmerged or an issue closed as not planned or a duplicate is `abandoned` (reported, never cleared).
  - The parsing invariant: for a recognised phrase (`blocked by`, `depends on`, `waiting on`, `blocked until`, `dependency:` / `needs dependency:`, and `do not merge before|until|prior to`), every reference-like token in its zone is either read as a blocker or the PR is marked incomplete, so `all_cleared` is never certified over text the parser could not read. What is deliberately not read: negated/historical phrases (`not blocked by`, `previously blocked by`), phrases with no reference-like token at all (`behaviour depends on the config`, `Dependency: bump`), and unrecognised phrasings (`blocked on`, `waiting for`, `stacked on`, `requires`). A PR whose references could not be read is listed (`blockers: []`) rather than dropped, and a `#N` link into another repository is never resolved here. Quoted lines (`> ...`) and collapsed text (`<details>...</details>`) are ignored and not read as the PR's own claims.
  - A failed read is never silence: a blocker that cannot be read is `unknown` (with a reason), its PR is listed, the output counts them, and the command exits 2.
