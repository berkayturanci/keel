- **`keel stale-blockers` lists open PRs whose stated blocker has cleared** (#1512). A PR body that says `blocked by #N`, `depends on #N` or `do not merge before #N|<tag>` is checked against GitHub. `/keel:stale-prs` and `/keel:morning` run it and surface the result.
  - A blocker is `cleared` when its PR merged, its issue closed as completed, or its tag exists; a PR closed unmerged or an issue closed as not planned or a duplicate is `abandoned` (reported, not counted as cleared).
  - The parser reads the recognised phrases (`blocked by`, `depends on`, `waiting on`, `blocked until`, `dependency:` / `needs dependency:`, and `do not merge before|until|prior to`) and marks a PR incomplete when it sees a reference it could not read in a phrase's zone. `all_cleared` is a best-effort hint for an operator to inspect, never a certificate: an operator must read the PR before acting. What is ignored: standard blockquotes (`> ...`), collapsed sections (`<details>...</details>`), negated/historical phrases (`not blocked by`, `previously blocked by`), phrases with no reference-like token at all (`behaviour depends on the config`, `Dependency: bump`), and unrecognised phrasings (`blocked on`, `waiting for`, `stacked on`, `requires`). Author alert blocks (`> [!NOTE]`, `> [!WARNING]`, etc.) are author claims and are scanned. A PR whose references could not be read is listed (`blockers: []`, `incomplete: true`) rather than dropped, and a `#N` link into another repository is treated as foreign and not resolved here.
  - A failed read is reported: a blocker that cannot be read is `unknown` (with a reason), its PR is listed, the output counts them, and the command exits 2.
