- **Drift checks line survival instead of warning on every shared file** (#1511). `verify_merge` now verifies line survival across every overtaking pull request per shared file using multiset counting against each overtaking PR's landed version. For each added line, its count in the merge commit must be >= its count in the PR's landed version; for each deleted line, its count in the merge commit must be <= its count in the PR's landed version (catching re-added deletions). Whole-file deletions (`+++ /dev/null`) and renamed-away paths are verified to be absent at both commits (`FILE_ABSENT`) and not to reappear in the merge commit, and metadata-only diffs (executable-bit mode changes and unchanged-content renames) are parsed without false drift. File absence is distinguished from unreadable content via `FILE_ABSENT` (using `git ls-tree --full-tree` for root-relative lookup), so unreadable content at either commit is reported as drift, never as a stayed deletion. Reports `clean (N shared files, 0 lost lines)` when all changes survive, and conservatively reports `drift` if added lines are missing, deleted lines are re-added, deleted files reappear, diffs are truncated or malformed (including truncated hunk headers after a completed hunk), or file content at either commit is unreadable — distinguishing `the shape of a silent revert` from `could not verify line survival (fail-closed)` in `reason`. The JSON report schema is bumped to `keel.merge-verify.v2`: `overtaken` maps `{path: [int, ...]}` to the overtaking PRs whose changes drifted on `path` (`{}` when `clean`; was `{path: int}` in v1), and reports add `shared_files` (`list[str]`) and PR-attributed `drift_details` (`dict[str, list[str]]`).
