- **Isolated review checkout for the `jury` gate and adapter reviewer guidance** (#1516). `swarm_runtime.review_checkout` and `jury.run_gate(..., head_sha=...)` allocate unique, invocation-owned detached checkouts under `.keel/worktrees/review-*` for the built-in `jury` gate (translating configuration-copy `OSError` failures into `ReviewCheckoutError`, copying `jury.toml`, `jury-policy.toml`, and `.jury/` entries only when untracked at the reviewed head and in the working-tree index, refusing on path collisions, and warning if worktree removal fails); the `ship` and `review-cycle` adapters recommend per-seat `.keel/worktrees/review-*` detached checkouts cleaned up via `keel worktree-remove` (with the `ship` adapter's `jury` panel, synchronous reviewer/gate, and detached launch/collect blocks failing closed on checkout, configuration-copy, dispatch, or cleanup errors before collection or evidence conversion, and detached collection removing the checkout only when `keel delegate wait` succeeds while leaving it in place and printing the cleanup command on timeout/failure).
- **Behaviour change — `keel ship` `jury` gate runs in a detached checkout** (#1516). When `keel ship` runs the `jury` gate, it executes `jury` in a fresh detached checkout of the reviewed commit (`--head-sha` or `HEAD`), copying `jury.toml`, `jury-policy.toml`, and `.jury/` entries from the repository root only when untracked at the checkout head and in the working-tree index (tracked configuration comes from the checkout itself, never from the working tree); uncommitted working-tree edits, tracked configuration introduced after `--head-sha`, and other untracked directories (e.g. `.keel/state`) are not visible to the panel.
